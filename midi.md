
# MIDI device

The Nano D++ has two MIDI interfaces:

- **USB MIDI** — Class-compliant, presented via `Adafruit_USBD_MIDI`. String descriptor: `"Nano_D MIDI"`. Initialized before threads start.
- **Hardware MIDI** — DIN/mini-jack via `Serial2` at 31250 baud (8N1). Assigned to `PIN_SERIAL2_RX` / `PIN_SERIAL2_TX`.

Both interfaces are handled by the `arduino-midi-library` (FortySevenEffects/arduino-midi-library). SysEx is supported on both interfaces via a shared handler.

---

## MIDI routing

Each interface has five boolean flags in `DeviceSettings` (`midiUsb` and `midi2` objects):

| Flag    | Meaning                                                    |
|---------|------------------------------------------------------------|
| `in`    | Receive MIDI on this interface (sets OMNI or OFF channel)  |
| `out`   | Send MIDI from this interface                              |
| `thru`  | Forward all incoming messages back out the same interface  |
| `route` | Route incoming to the other interface                      |
| `nano`  | The Nano D++ itself sends/receives MIDI on this interface  |

Routing logic (evaluated in `hmi_thread` each iteration):

```
if midiUsb.route && midi2.out:
    midi2 ← message received on USB MIDI

if midi2.route && midiUsb.out:
    midiUsb ← message received on hardware MIDI
```

Thru mode is applied via `setThruFilterMode(Thru::Full)` or `Thru::Off` on each instance.

To set channel: `in=true` uses `MIDI_CHANNEL_OMNI`; `in=false` uses `MIDI_CHANNEL_OFF`.

## MIDI messages generated by the device

### Knob (CC)

When the knob value type is `"midi"`, a Control Change is sent on every position change when `currentValue != lastValue`:

- Value is the mapped float, cast to `uint8_t` and clamped to [0, 127].
- Sent on `midiu` if `midiUsb.nano = true`.
- Sent on `midi2` if `midi2.nano = true`.

```json
{ "type": "midi", "channel": 1, "cc": 7 }
```

### Key (CC)

Key actions of type `"midi"` send CC on press only:

```json
{ "type": "midi", "channel": 1, "cc": 7, "val": 127 }
```

## MIDI SysEx

SysEx messages arriving on either interface are dispatched to `HmiThread::handleSysex()`. The handler checks bytes [0], [1], [2] against `SYSEX_BINARIS_ID`, `SYSEX_NANO_ID`, and the configured `midi_sysex_id` (from `DeviceSettings.midi_sysex_id` / `sysexId` settings field). Matching messages are currently logged; handling of specific SysEx commands is not yet implemented.

---

## Settings via JSON

MIDI interface settings are part of `DeviceSettings` and are read/written via the `{"settings":{...}}` command:

```json
{
  "midiUsb": { "in": true,  "out": true, "thru": false, "route": false, "nano": true },
  "midi2":   { "in": false, "out": true, "thru": false, "route": true,  "nano": true },
  "sysexId": 0
}
```

Changes take effect immediately; the HMI thread applies them on its next `handleSettings()` tick.
